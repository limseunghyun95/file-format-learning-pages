Interview

“왜 Parquet가 빠른가?”에 columnar라는 한 단어가 아니라 실제 skip/read/decode 단계를 답한다.

파일 포맷은 확장자가 아니라 producer와 consumer 사이의 장기 계약이며, data layout은 쿼리 비용 모델이다.

큰 그림: SQL이 결과가 되기까지

아키텍처 그림은 “파일을 연다”를 단계로 분해한다. 최적화가 적용되는 위치와 오류가 생기는 위치가 다르기 때문이다.

Schema evolution시간이 지나 field가 변해도 과거·신규 데이터를 안전하게 해석하는 규칙. 단순 schema inference가 아니다.

Dictionary Fallback고유값이 늘어 dictionary가 비효율적이 되면 writer가 plain encoding 등으로 전환하는 동작. 파일 전체가 하나의 encoding만 쓰는 것은 아니다.
Selection Vectorvectorized engine이 filter를 통과한 row 위치를 모아 다음 operator에 전달하는 인덱스 배열·bitmap. 값을 한 row씩 복사하는 비용을 줄인다.
Range Readobject 전체가 아니라 byte offset 구간만 가져오는 읽기. footer와 선택 column chunk만 읽는 columnar scan의 원격 I/O 기반이다.

Deep Dive: byte layout에서 query cost까지

“Parquet라서 빠르다”는 답은 부족하다. 어떤 metadata가 어느 단위를 제거하고, 남은 byte가 어떻게 decode되어 CPU register가 처리하는지까지 이어져야 한다.

1 · Logical → physical

DECIMAL(18,2), date, timestamp 같은 logical type은 INT32/INT64/fixed byte array 같은 physical representation 위에 의미를 얹는다. Reader가 annotation을 잃거나 timezone·scale을 다르게 해석하면 byte는 정상이어도 값은 틀릴 수 있다. 따라서 schema는 field 이름뿐 아니라 nullability, precision/scale, timezone semantics까지 계약해야 한다.

2 · Nested encoding

list<struct<id, tag?>>는 row object를 통째로 저장하지 않는다. leaf column 값과 definition/repetition level stream으로 null·empty list·새 element·새 row 경계를 복원한다. projection이 nested path 일부만 읽을 때도 level을 함께 읽어 구조를 재조립해야 한다.

3 · Statistics correctness

Min/max는 값 범위가 query predicate와 겹치지 않을 때 row group을 제거한다. 하지만 null, NaN, truncated bound, collation, unsigned/decimal 해석, 오래된 writer bug를 고려해야 한다. Statistics는 “정답 index”가 아니라 false negative가 없어야 하는 skip hint이며 신뢰할 수 없으면 읽는 쪽으로 보수적으로 fallback한다.

4 · Vectorized read

Reader는 page를 decompress하고 definition level·dictionary/RLE/plain 값을 column vector에 decode한다. Filter는 vector batch에 적용되고 selection vector가 살아남은 row를 가리킨다. row-at-a-time virtual call과 branch를 줄이고 cache locality/SIMD 가능성을 높이지만, wide variable-length column·nested materialization·작은 batch에서는 이득이 줄 수 있다.

5 · Schema resolution

Avro는 writer schema와 reader schema를 함께 사용해 field name/alias/default 규칙으로 값을 해석한다. Protobuf는 field number와 wire type을 통해 unknown field를 보존할 수 있다. Compatibility tool이 syntax를 통과시켜도 단위 변경, 의미 변경, required business invariant는 검출하지 못하므로 semantic contract test가 필요하다.

6 · Object storage cost

대량 scan 비용은 LIST + HEAD/GET request 수 + transferred bytes + decompression CPU + task scheduling의 합이다. 1TB 한 파일은 병렬성과 recovery unit이 나쁘고, 1KB 파일 10억 개는 request/planning 비용이 지배한다. target file/row-group size는 engine split, network, memory, update pattern을 함께 보고 정한다.

최종 캡스톤: 포맷 의사결정이 보이는 데이터 레이크

Pipeline

CSV/NDJSON raw ingestion → explicit schema validation → quarantine → partitioned Parquet curated zone → DuckDB query.

Evidence

10M+ rows에서 bytes read, planning time, CPU, compression ratio, p95 query latency, reject rate를 비교한다.

Failure drill

schema drift, corrupt footer, partial publish, small-file explosion을 넣고 탐지·격리·재처리·재발 방지를 수행한다.

  1. 요구사항과 데이터 특성을 먼저 말한다.
  2. logical value → physical layout → read path를 연결한다.
  3. 성능 주장을 자신의 benchmark와 profiler 증거로 뒷받침한다.
  4. compatibility와 data quality를 기술 문제가 아닌 조직 계약으로 설명한다.
  5. format과 table format, storage와 catalog의 책임 경계를 구분한다.
