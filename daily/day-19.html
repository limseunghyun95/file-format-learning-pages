default, optional, unknown field

Byte presence에서 API·business semantics까지 · 예상 학습 60분 + 실습 35분
한 줄 요약
값이 0인 것, field가 wire에 없는 것, 0으로 명시 설정된 것, reader가 모르는 field는 서로 다른 상태다. 이 경계를 보존하지 않으면 parser는 성공해도 PATCH가 적용되지 않고, old proxy가 새 field를 지우며, 같은 Avro bytes가 reader default 변경만으로 다른 business value가 될 수 있다.

1. 선수 용어 사전

Default value값이 없을 때 API 또는 reader가 보여 주는 기본값이다. Protobuf scalar의 API default와 Avro reader default는 작동 시점·byte 규칙이 다르다.

2. 왜 중요한가

결제 한도를 100에서 0으로 지우는 PATCH를 생각하자. API가 implicit presence라면 limit=0은 serialize에서 사라지고 merge에서도 skip될 수 있다. Server는 이를 “변경 없음”으로 받아 기존 100을 유지한다. HTTP 200과 protobuf parse 성공에도 업무 결과는 틀렸다.

또한 new producer가 field 3을 추가하고 old relay가 message를 읽어 JSON으로 바꾼 뒤 다시 binary로 만들면, old relay가 몰랐던 field 3은 사라질 수 있다. 장애는 relay가 아니라 downstream의 “신규 field missing”으로 늦게 나타난다. 따라서 unknown 보존 여부는 data path 전체의 속성이다.

오늘의 핵심 불변식: absent, explicit default, null, unknown을 한 상태로 접지 않는다. 변환 단계마다 어느 상태를 입력받고, 무엇을 보존하며, 어디서 business default를 적용했는지 증거를 남긴다.

4. CS 내부 동작

4.1 Wire에는 “없음” byte가 없다

Protobuf binary는 tag=(field_number<<3)|wire_type와 payload의 연속이다. Stream에 tag가 보이면 present이며, 보이지 않으면 그 field에 대한 정보가 없다. “명시적으로 unset”이라는 별도 byte는 없다. 따라서 absence를 구분하려면 API가 presence bit를 추적하거나 oneof, wrapper, FieldMask 같은 protocol을 설계해야 한다.

Caller/API 상태Implicit int32optional int32
UnsetGetter 0, bytes 없음Getter 0, has=false, bytes 없음
Set 0Getter 0, bytes 없음Getter 0, has=true, bytes 08 00
Set 7Getter 7, bytes 08 07Getter 7, has=true, bytes 08 07

4.2 Merge와 PATCH의 함정

Implicit presence에서 default는 serialization뿐 아니라 merge-from에서도 빠진다. source.limit=0을 target에 merge해도 target의 100이 남을 수 있다. PATCH는 body만 믿지 말고 FieldMask(paths=["limit"])나 명시적 command를 함께 보내 “0으로 변경”을 표현한다. 반대로 field가 mask에 없으면 body에 값이 있어도 변경하지 않는다는 우선순위를 문서화한다.

4.3 Unknown field는 forward compatibility buffer다

Old parser는 모르는 tag의 wire type을 이용해 payload 경계를 건너뛰고 unknown set에 보관할 수 있다. 같은 message object를 binary로 재직렬화하면 unknown도 다시 나간다. 하지만 field-by-field로 새 object를 만들거나 ProtoJSON을 거치면 unknown이 유실될 수 있다. Copy API와 binary pass-through를 쓰고, relay에서 unknown byte count와 round-trip test를 운영 지표로 둔다.

Unknown은 schema 검증을 우회하는 비밀 저장소가 아니다. Type과 의미를 모으므로 business validation, PII 분류, canonical hash를 적용하기 어렵다. 장기 보관·보안 경계에서는 허용 크기, nesting, field count와 retention을 제한한다.

4.4 Avro default는 reader가 실행한다

Avro record는 writer schema 순서로 모든 field value를 encode한다. 값이 default와 같아도 field는 encode되며, default가 있다고 writer 입력을 생략할 수 있는 것이 아니다. Reader schema에만 field가 있고 writer schema에 없다면 그때 reader default가 materialize된다. Reader default가 없으면 resolution error다.

같은 bytes, 다른 결과: W1 bytes에 currency가 없다. R2 default가 KRW면 KRW, R3 default가 USD면 USD가 된다. Bytes는 변하지 않았지만 reader policy가 의미를 바꾼다. 따라서 default 변경도 data migration처럼 version·replay 영향과 rollback을 검토한다.

4.5 Null·absent·default·unknown의 네 상태

  • Absent: wire에 field가 없고 API가 unset을 추적할 수도, 못 할 수도 있다.
  • Explicit default: 값은 0/empty지만 optional API에서는 present다.
  • Null: Schema가 허용한 명시적 logical value다. “안 보냄”과 동일시하지 않는다.
  • Unknown: Wire에는 존재하지만 현재 reader가 의미를 모른다. Absent의 반대편에 가깝다.

5. 실무 설계 판단

판단Best practice와 이유
Presence가 의미인가?Unset과 zero/empty가 다르면 proto3 basic field에 explicit presence를 쓰고 generated has/clear API를 사용한다.
PATCH인가?Full replacement와 partial update message를 분리하고 FieldMask 또는 command enum으로 no-op/set/clear를 명시한다.
Relay가 있는가?Binary message-oriented copy를 쓰고 unknown-preservation contract test를 old/new runtime마다 실행한다. JSON bridge는 schema evolution 경계로 취급한다.
Avro field 추가?Reader default가 old record에 실제로 어떤 업무 값을 만들지 검토한다. Writer는 새 schema의 모든 field를 encode하도록 한다.
Default 변경?Retained generation을 새 reader로 replay해 aggregate 차이를 측정하고 reader version을 결과 metadata에 기록한다.
Unknown 허용?Size/depth/count budget과 telemetry를 둔다. Security boundary에서는 typed validation 전까지 sink 적용을 금지한다.
완료 판정?Parse rate뿐 아니라 presence distribution, unknown bytes, PATCH intent/result, replay aggregate와 rollback reader까지 확인한다.

Anti-pattern·edge case·runtime 차이

  • Getter가 0이면 unset: Implicit API에서는 명시 0과 unset을 구분할 증거가 없다.
  • Default가 optional을 만든다: Avro default는 encode-time optional이 아니고, Protobuf API default도 nullability가 아니다.
  • Unknown은 old reader가 무조건 보존: Binary message 왕복은 가능해도 JSON·field-by-field copy·일부 bridge에서 사라진다.
  • Unknown을 error로 전부 거부: Forward compatibility를 끊는다. 외부 security boundary와 내부 compatible relay의 정책을 분리한다.
  • Unknown을 무제한 허용: Memory·CPU amplification과 숨은 PII 보관 위험이 생긴다.
  • Default 값을 바꿔도 bytes는 같으니 안전: Avro old bytes의 read-time business result가 바뀐다.
  • Empty list와 absent list 구분: Protobuf repeated/map은 일반적으로 explicit presence를 추적하지 않는다.
  • Message field도 scalar처럼 implicit: Singular message는 presence를 추적한다. Field 종류별 표를 확인한다.
  • Enum UNKNOWN이면 모든 미래 값 안전: 언어/runtime의 unknown enum API와 exhaustive switch 동작을 matrix로 확인한다.
  • Binary equality로 round-trip 검증: Protobuf field order는 canonical하지 않을 수 있으므로 semantic equality와 unknown set 보존을 본다.

7. 35분 실습: presence·unknown·reader default를 byte로 증명

목표: Python 표준 라이브러리만으로 implicit/explicit 0의 byte 차이, unknown field 보존/유실, Avro-like reader default의 read-time 동작을 재현한다.

사전 조건: Python 3.9 이상. 외부 package나 protoc는 필요 없다. 교육용 model이며 production runtime을 대체하지 않는다.

실행 전 예측: Implicit 0과 unset의 hex, explicit 0의 hex, old proxy가 unknown field 3을 field-by-field copy할 때의 결과, 같은 old record를 KRW/USD default로 읽은 결과를 먼저 적는다.

python3 - <<'PY' def varint(n): out = bytearray() while n > 0x7f: out.append((n & 0x7f) | 0x80); n >>= 7 out.append(n); return bytes(out) def fvar(no, value): return varint((no << 3) | 0) + varint(value) def fstr(no, value): raw = value.encode() return varint((no << 3) | 2) + varint(len(raw)) + raw def readv(buf, p): n = 0 for i in range(10): if p >= len(buf): raise ValueError("TRUNCATED_VARINT") b = buf[p]; p += 1; n |= (b & 0x7f) << (7*i) if b < 128: return n, p raise ValueError("OVERLONG_VARINT") def parse(buf, known, max_len=128): p, values, present, unknown = 0, {}, set(), [] while p < len(buf): start = p; key, p = readv(buf, p) no, wire = key >> 3, key & 7 if no == 0 or wire not in (0, 2): raise ValueError("BAD_TAG") if wire == 0: value, p = readv(buf, p) else: size, p = readv(buf, p) if size > max_len or size > len(buf)-p: raise ValueError("BAD_LEN") value, p = buf[p:p+size].decode(), p+size raw = buf[start:p] if no in known: values[known[no]] = value; present.add(known[no]) else: unknown.append((no, wire, value, raw)) return values, present, unknown implicit_unset = b"" implicit_zero = b"" # API value 0은 default라 생략 explicit_unset = b"" explicit_zero = fvar(1, 0) # optional field가 present면 0도 기록 for name, raw in [("implicit_unset", implicit_unset), ("implicit_zero", implicit_zero), ("explicit_unset", explicit_unset), ("explicit_zero", explicit_zero)]: value, present, unknown = parse(raw, {1:"limit"}) print(name, "hex=", raw.hex(" ") or "<empty>", "getter=", value.get("limit", 0), "has=", "limit" in present) new_bytes = fvar(1, 7) + fstr(3, "future") known, present, unknown = parse(new_bytes, {1:"id"}) binary_proxy = fvar(1, known["id"]) + b"".join(x[3] for x in unknown) manual_copy = fvar(1, known["id"]) print("new= ", new_bytes.hex(" ")) print("binary_proxy=", binary_proxy.hex(" "), "unknown_preserved=", binary_proxy == new_bytes) print("manual_copy= ", manual_copy.hex(" "), "unknown_lost=", manual_copy != new_bytes) def avro_like_resolve(writer_record, reader_fields): out = {} for name, spec in reader_fields.items(): if name in writer_record: out[name] = writer_record[name] elif "default" in spec: out[name] = spec["default"] else: raise ValueError("NO_DEFAULT:" + name) return out old = {"amount": 1000} for default in ("KRW", "USD"): r = {"amount": {}, "currency": {"default": default}} print("same_old_record reader_default=", default, "->", avro_like_resolve(old, r)) try: avro_like_resolve(old, {"amount": {}, "currency": {}}) except Exception as e: print("missing_without_default=", e) PY

예상 관찰: Implicit unset과 implicit zero는 모두 empty bytes·getter 0이라 구분되지 않는다. Explicit zero만 08 00과 has=true다. Binary proxy는 unknown field 3 raw bytes를 보존하지만 manual copy는 잃는다. 같은 old record도 reader default에 따라 통화가 달라진다.

7.2 실패 주입: PATCH와 corrupt unknown

python3 - <<'PY' def apply_patch(current, body, mask): result = dict(current) for path in mask: if path not in body: raise ValueError("MASK_WITHOUT_VALUE:" + path) result[path] = body[path] return result current = {"limit": 100} print("body-only implicit merge ->", current) # 0이 wire에서 빠졌다고 가정 print("body+mask explicit set 0 ->", apply_patch(current, {"limit":0}, ["limit"])) # field 3, LEN=10이라고 선언했지만 payload는 2 bytes뿐인 corrupt unknown bad = bytes.fromhex("1a 0a 6f 6b") size, remaining = bad[1], len(bad)-2 print("unknown_length=", size, "remaining=", remaining) if size > remaining: print("REJECT BAD_LEN before cursor commit") PY

안전 관찰: Presence 없는 body만으로는 0 적용 intent가 사라진다. Mask를 함께 쓰면 0을 명시 적용한다. Unknown이라고 무조건 skip하지 말고 length가 frame remaining과 budget 안에 있는지 검사한 뒤 cursor를 commit한다.

7.3 자주 나는 오류와 해결·cleanup

  • HTML에서 <<가 깨짐: 코드의 특수문자를 escape한 원문으로 실행한다.
  • Byte equality만 실패: Field order가 달라질 수 있으니 known values, presence, unknown raw set을 함께 비교한다.
  • Default를 writer 입력에 자동 삽입: Avro writer contract와 reader resolution simulation을 분리한다.
  • Unknown payload log 노출: 운영에서는 field number·wire type·size·hash만 기본 기록하고 raw PII는 보호 저장소로 격리한다.

Cleanup: 두 명령은 파일·package·container를 만들지 않는다. 실제 production payload는 terminal과 CI log에 붙여 넣지 않는다.

8. 놓치기 쉬운 함정

  1. Wire absence와 API default getter를 같은 증거로 보지 않는다.
  2. Explicit 0을 preserve하려면 value뿐 아니라 presence를 테스트한다.
  3. PATCH body와 FieldMask의 충돌 우선순위를 정한다.
  4. Unknown 보존은 개별 parser가 아니라 end-to-end path의 속성이다.
  5. JSON gateway를 단순 표현 변환이 아니라 compatibility boundary로 본다.
  6. Avro default는 old bytes를 읽을 때만 쓰며 writer field 생략 허가가 아니다.
  7. Reader default 변경은 historical replay 결과를 바꾼다.
  8. Null은 union/schema가 허용한 value이고 absent와 다르다.
  9. Repeated/map empty와 absent는 일반적으로 presence로 구분되지 않는다.
  10. Round-trip 성공 기준에 unknown·business intent·DB 결과를 포함한다.

9. 대기업 기술 면접 질문

Q1. Proto3에서 int32 limit=1과 optional int32 limit=1을 PATCH API 관점에서 비교하세요.

좋은 답변 구조: Wire는 present tag-value만 가진다고 정의한다 → unset/set 0/set 7의 bytes와 API has state를 그린다 → implicit merge가 0을 skip하는 실패를 설명한다 → FieldMask·explicit presence·command message 대안을 비교한다 → rollout, old client, metrics와 rollback까지 말한다.

Q2. Old proxy가 new field를 모를 때 forward compatibility를 어떻게 보장합니까?

좋은 답변 구조: Old parser의 bounded unknown skip과 opaque set을 설명한다 → binary message-oriented copy와 JSON/manual copy를 대비한다 → max size·PII·canonical hash trade-off를 짚는다 → old/new runtime golden round-trip과 unknown byte telemetry를 제시한다 → 손실 generation quarantine/replay 복구를 방어한다.

Q3. Avro reader default를 KRW에서 USD로 바꾸는 변경을 리뷰하세요.

좋은 답변 구조: Default는 writer omission이 아니라 missing writer field의 read-time resolution임을 밝힌다 → 보관 데이터량·writer generations·replay SLA를 수치로 묻는다 → same bytes/different reader result를 보인다 → aggregate shadow read와 versioned metadata를 설계한다 → dual read, migration, rollback pointer와 reconciliation을 제안한다.
