binary serialization, varint, zig-zag

Logical integer에서 wire bytes·bounded decoder까지 · 예상 학습 55분 + 실습 35분
한 줄 요약
Binary serialization은 값을 “0과 1로 바꾸는 것”이 아니라 schema가 정한 field identity·wire type·length·integer encoding으로 message boundary를 복원 가능하게 만드는 계약이며, varint와 zig-zag는 값 분포에 따라 byte 수를 줄이는 서로 다른 단계다.

1. 선수 용어 사전

용어쉬운 설명과 정확한 정의
SerializationMemory의 object·record를 저장·전송 가능한 byte sequence로 만드는 과정이다. Field 순서·type·경계와 누락/unknown 처리 규칙이 필요하다.
Binary format값과 경계를 문자 token이 아닌 bit/byte layout으로 표현하는 포맷이다. 암호화라는 뜻도, 항상 더 작다는 뜻도 아니다.

2. 왜 중요한가

Text에서는 integer 300을 ASCII bytes 33 30 30으로 표현한다. Unsigned varint에서는 AC 02 두 bytes다. 그러나 값이 매우 크거나 음수 policy가 맞지 않으면 varint가 fixed-width보다 커질 수 있다. “Binary는 작고 빠르다”가 아니라 실제 값 분포, branch 비용, schema evolution과 decoder 안전성으로 판단해야 한다.

Binary bytes에는 눈에 보이는 comma나 newline이 없다. Decoder가 한 length를 잘못 읽으면 이후 모든 field boundary가 밀린다. 악성 input이 거대한 length를 선언하거나 종료 bit가 없는 varint를 보내면 memory allocation·CPU loop·out-of-bounds 위험이 생긴다. 따라서 bounds check는 보안 옵션이 아니라 문법 정확성의 일부다.

오늘의 핵심 불변식: Decoder는 매 단계에서 0 ≤ cursor ≤ message_length를 유지하고, varint byte 수·length-delimited 크기·nesting depth를 제한하며, 성공 시 정확히 정의된 boundary에서 멈춘다. 실패 입력에서도 임의 bytes를 값으로 만들거나 cursor를 확정하지 않는다.

3. 아키텍처 그림과 요청 흐름

Data path: logical value → zig-zag/fixed transform → varint/bytes → field framing → message → storage/network → decode.
Control path: schema version, field numbers, logical types, default/presence, max size/depth, unknown-field policy와 rollout 순서를 전달한다.
  1. Schema lookup: Writer는 field name이 아니라 field number와 declared type을 가져온다. 같은 number의 의미는 생명주기 전체에서 안정적이어야 한다.
  2. Value transform: Signed 값이라면 schema가 정한 int/sint/fixed 계열에 따라 two's-complement 또는 zig-zag를 적용한다.
  3. Physical encoding: Unsigned 값은 varint 또는 fixed width로, string/bytes는 length prefix + payload로 만든다.
  4. Field assembly: Protobuf 예에서는 (field_number << 3) | wire_type을 varint key로 쓴다. Key는 decoder가 모르는 field도 건너뛰게 한다.
  5. Outer framing: Message 자체의 끝을 transport가 알아야 한다. TCP stream에는 message boundary가 없으므로 별도 length prefix나 envelope가 필요하다.
  6. Decode/commit: Reader는 bounds 안에서 key와 value를 읽고 schema로 logical value를 복원한다. 전체 validation 뒤에만 downstream state와 checkpoint를 확정한다.

4. CS 내부 동작

4.1 Varint는 7-bit group state machine이다

Encoder는 unsigned integer의 낮은 7 bits를 꺼내 byte에 넣고, 남은 값이 있으면 MSB를 1로 세운다. 값을 7 bits 오른쪽으로 이동하며 0이 될 때까지 반복한다. Decoder는 각 byte의 낮은 7 bits를 shift=0, 7, 14… 위치에 OR하고 MSB가 0인 첫 byte에서 끝난다.

값7-bit groupsWire hex크기
10000001011 byte
12711111117F1 byte
1280000000, 000000180 012 bytes
3000101100, 0000010AC 022 bytes

작은 값에는 유리하지만 byte마다 continuation branch와 shift/OR가 필요하다. Random한 큰 64-bit 값은 9~10 bytes가 될 수 있어 fixed64 8 bytes보다 크고 decode도 복잡하다. Compression 전 raw size와 CPU/cache behavior를 실제 분포로 측정한다.

4.2 Zig-zag는 compression이 아니라 signed→unsigned mapping이다

32-bit 개념식은 (n << 1) ^ (n >> 31)이다. 결과는 0→0, -1→1, 1→2, -2→3, 2→4가 된다. 0 주변의 작은 음수도 작은 unsigned 값이 되어 varint가 짧아진다. Zig-zag만 적용하면 아직 integer일 뿐이고, 그 결과를 varint로 써야 wire bytes가 된다.

반대로 counter, ID처럼 음수가 없거나 최솟값에서 멀리 분포하는 값에는 zig-zag가 불필요하다. Schema의 int32와 sint32는 논리상 정수라도 wire mapping이 다르므로 이름만 바꾸는 식의 type 변경을 호환으로 간주하면 안 된다.

4.3 Field key는 schema evolution을 위한 local framing이다

Protobuf wire key는 field number와 wire type을 결합한다. 예를 들어 field 1, wire type 0은 key 08이고 field 2, wire type 2는 key 12다. Old reader는 모르는 field 9를 만나도 wire type을 보고 해당 value의 bytes를 건너뛴 뒤 다음 key에서 재동기화할 수 있다.

하지만 wire type만으로 business 의미를 알 수는 없다. 같은 varint wire type 안에도 bool, enum, int, sint가 존재할 수 있다. Wire-level skip 가능성과 semantic compatibility는 별도 검토다.

4.4 Length-delimited는 allocation 명령이 아니다

Length prefix가 2GB라고 선언됐다고 즉시 2GB buffer를 할당하면 안 된다. 먼저 protocol/config limit, 현재 frame의 remaining bytes, application field limit을 비교한다. length ≤ remaining이 아니면 truncated input이고, limit을 넘으면 oversize다. 검증 후에도 bounded slice 또는 streaming decode를 사용한다.

4.5 Message framing은 wire field framing과 별개다

한 Protobuf message의 내부 fields는 self-delimiting할 수 있지만, TCP byte stream에서 message A가 어디서 끝나고 B가 시작하는지는 별도 정보가 필요하다. RPC envelope, Kafka record length, file container block 등이 이 outer frame을 소유한다. read() 한 번이 message 하나라는 가정은 partial read와 coalescing에서 깨진다.

4.6 Deterministic bytes와 semantic equality를 구분한다

두 messages가 같은 logical fields를 나타내도 field ordering, unknown fields, map ordering이나 library option에 따라 bytes가 다를 수 있다. Byte hash를 business identity로 쓰기 전에 deterministic serialization 보장 범위와 version을 확인한다. 서명·cache key가 필요하면 canonicalization policy와 golden bytes를 계약으로 둔다.

Anti-pattern·edge case·version 차이

  • Binary=압축/암호화: Serialization, compression, encryption을 서로 다른 계층과 실패 원인으로 분리한다.
  • 음수에 unsigned varint: Sign extension 때문에 길어질 수 있다. Declared signed encoding을 확인한다.
  • Length만 믿고 allocation: Memory exhaustion과 truncated read를 만든다.
  • 종료 bit까지 무한 loop: Integer 폭에 맞는 최대 varint bytes를 강제한다.
  • Field number 재사용: Old bytes를 새 의미로 조용히 해석하는 semantic corruption이 된다.
  • Unknown field 무조건 삭제: Old proxy를 통과할 때 forward-compatible data가 손실될 수 있다.
  • Decode 성공=valid data: Required business rule, enum range, timestamp/unit와 cross-field invariant는 별도다.
  • Byte equality=object equality: Deterministic option과 implementation/version 범위를 확인한다.
  • Library별 limits 동일 가정: Max size/depth, recursion, unknown preservation, duplicate singular field와 malformed varint 처리에는 구현·버전 차이가 있을 수 있다.

실행 전 예측: 127/128/300의 varint hex, -1/-2/-150의 zig-zag 결과, 완성 message의 bytes를 종이에 먼저 적는다. Truncated varint와 거짓 length가 cursor에 어떤 영향을 주는지도 예측한다.

7.1 Bounded encoder/decoder 구현

mkdir -p /tmp/file-format-day15 cd /tmp/file-format-day15 python3 - <<'PY' from pathlib import Path program = r'''MAX_U64_VARINT_BYTES = 10 MAX_FIELD_BYTES = 1024 class WireError(Exception): pass def enc_uvarint(n): if not 0 <= n < 1 << 64: raise WireError("UINT64_RANGE") out = bytearray() while True: low = n & 0x7f n >>= 7 out.append(low | (0x80 if n else 0)) if not n: return bytes(out) def dec_uvarint(buf, pos=0): value = 0 for i in range(MAX_U64_VARINT_BYTES): if pos >= len(buf): raise WireError("TRUNCATED_VARINT") b = buf[pos]; pos += 1 if i == 9 and (b & 0x80): raise WireError("VARINT_TOO_LONG") if i == 9 and b > 1: raise WireError("VARINT_OVERFLOW") value |= (b & 0x7f) << (7 * i) if not (b & 0x80): return value, pos raise WireError("VARINT_TOO_LONG") def zigzag32(n): if not -(1 << 31) <= n < (1 << 31): raise WireError("INT32_RANGE") return ((n << 1) ^ (n >> 31)) & 0xffffffff def unzigzag(n): return (n >> 1) ^ -(n & 1) def field_key(number, wire_type): if number <= 0: raise WireError("FIELD_NUMBER") return enc_uvarint((number << 3) | wire_type) def length_delimited(raw): if len(raw) > MAX_FIELD_BYTES: raise WireError("FIELD_TOO_LARGE") return enc_uvarint(len(raw)) + raw def parse(buf): pos, fields = 0, [] while pos < len(buf): key, pos = dec_uvarint(buf, pos) number, wire_type = key >> 3, key & 7 if number == 0: raise WireError("FIELD_NUMBER") if wire_type == 0: value, pos = dec_uvarint(buf, pos) fields.append((number, wire_type, value)) elif wire_type == 2: length, pos = dec_uvarint(buf, pos) if length > MAX_FIELD_BYTES: raise WireError("FIELD_TOO_LARGE") if length > len(buf) - pos: raise WireError("LENGTH_EXCEEDS_FRAME") fields.append((number, wire_type, buf[pos:pos+length])) pos += length else: raise WireError("UNSUPPORTED_WIRE_TYPE") assert pos == len(buf) return fields message = ( field_key(1, 0) + enc_uvarint(zigzag32(-150)) + field_key(2, 2) + length_delimited(b"hi") ) print("varints=", {n: enc_uvarint(n).hex(" ") for n in [1, 127, 128, 300, 16384]}) print("zigzag=", {n: zigzag32(n) for n in [0, -1, 1, -2, 2, -150]}) print("message=", message.hex(" ")) print("fields=", parse(message)) decoded = {} for number, wt, value in parse(message): if number == 1: decoded["temperature"] = unzigzag(value) elif number == 2: decoded["note"] = value.decode("utf-8", "strict") print("decoded=", decoded) assert message.hex() == "08ab0212026869" assert decoded == {"temperature": -150, "note": "hi"} # Old reader가 모르는 field 9(varint 7)를 wire type으로 skip할 수 있다. with_unknown = message + field_key(9, 0) + enc_uvarint(7) print("with_unknown=", with_unknown.hex(" "), parse(with_unknown)) ''' Path("wire_lab.py").write_text(program, encoding="utf-8") PY python3 wire_lab.py

7.2 실패 주입과 fixed-width 비교

cd /tmp/file-format-day15 python3 - <<'PY' import struct from wire_lab import enc_uvarint, parse, WireError for n in [1, 127, 128, 300, (1 << 32) - 1]: print(n, "varint_bytes=", len(enc_uvarint(n)), "fixed32_bytes=", len(struct.pack("<I", n))) cases = { "truncated_varint": bytes.fromhex("08 80"), "varint_too_long": bytes.fromhex("08") + b"\x80" * 10, "varint_overflow": bytes.fromhex("08") + b"\x80" * 9 + b"\x02", "length_exceeds_frame": bytes.fromhex("12 05 68 69"), "unsupported_wire_type": bytes.fromhex("0f") } for name, raw in cases.items(): try: print(name, parse(raw)) except WireError as e: print(name, "REJECT", str(e)) PY

예상 관찰: 작은 값은 varint가 1~2 bytes지만 2^32-1은 5 bytes라 fixed32보다 크다. 실패들은 각각 TRUNCATED_VARINT, VARINT_TOO_LONG, VARINT_OVERFLOW, LENGTH_EXCEEDS_FRAME, UNSUPPORTED_WIRE_TYPE으로 안정되게 거부된다. Decoder는 입력을 고치거나 다음 byte로 임의 resync하지 않는다.

7.3 자주 나는 오류와 해결·cleanup

  • AC 02를 big-endian integer처럼 읽음: 각 byte의 낮은 7-bit group을 낮은 자리부터 조립한다.
  • Zig-zag와 varint를 한 단계로 설명: Signed→unsigned mapping과 unsigned→variable bytes를 분리해 중간값을 출력한다.
  • 10번째 byte overflow 누락: 64-bit varint 마지막 byte에는 허용 가능한 값 범위를 추가 검사한다.
  • Length slice 전에 allocation: Limit과 remaining을 먼저 검사하고 bounded slice를 만든다.
  • Import 때 demo 출력: Production module은 실행부를 if __name__ == "__main__"로 분리한다. 실습은 관찰을 위해 단순화했다.

8. 놓치기 쉬운 함정

  1. Varint는 integer 안의 redundancy를 줄일 뿐 message 자체의 compression codec이 아니다.
  2. Zig-zag는 signed 값을 정렬해 mapping할 뿐 overflow range와 logical unit을 검증하지 않는다.
  3. Wire type이 같다고 schema type 변경이 호환인 것은 아니다. Int와 sint는 같은 logical 숫자도 bytes/해석이 다르다.
  4. Length-delimited payload 내부가 UTF-8 string인지 nested message인지 bytes인지는 reader schema가 결정한다.
  5. Embedded message마다 recursion depth와 aggregate decoded size를 함께 제한한다.
  6. Unknown-field skip 가능성과 read-modify-write 보존은 별도 capability다.
  7. Partial network read를 malformed complete frame으로 확정하지 않는다. Outer framer가 complete 여부를 소유한다.
  8. Decode error offset을 기록하되 전체 secret/PII payload를 log에 남기지 않는다.
  9. Schema registry의 wire compatibility가 enum meaning, unit, timezone, required business invariant까지 보장하지 않는다.

9. 대기업 기술 면접 질문

Q1. Varint와 fixed32 중 무엇을 선택하겠습니까?

좋은 답변 구조: 값 분포·signed 여부·messages/s·CPU SLO를 먼저 묻는다 → varint의 7-bit loop와 fixed32의 4-byte load를 설명한다 → 작은 값 size 이점과 큰 값 5-byte/branch 비용을 수치화한다 → compression/cache/network를 포함한 benchmark를 설계한다 → zig-zag, delta, fixed-width 대안과 malformed limits까지 말한다.

Q2. Binary decoder를 untrusted input에 안전하게 설계하세요.

좋은 답변 구조: Outer frame owner와 trust boundary를 정한다 → cursor≤frame, max varint/message/field/count/depth 불변식을 둔다 → length를 remaining과 비교하고 allocation 전 검증한다 → stable reason·bounded evidence·quarantine를 설계한다 → fuzz/property/golden tests, CPU/memory metrics, rollback과 idempotent replay를 포함한다.

Q3. 새 field를 추가했는데 old proxy를 지나며 값이 사라졌습니다. 원인은?

좋은 답변 구조: Wire-level unknown skip과 object round-trip preservation을 구분한다 → producer→old proxy decode/modify/re-encode→new consumer 흐름을 그린다 → library/version/JSON bridge/drop policy 가설을 세운다 → exact bytes와 unknown count를 수집한다 → reader-first 배포, golden round-trip, reserved number, rollback과 raw envelope 보존 대안을 제시한다.

10. 복습과 정답

  2. CSV dialect contract를 bytes·문법·schema·운영 네 계층으로 나눠 말하라.
  3. Delimiter 변경을 old/new writer×reader matrix와 rollback으로 어떻게 배포하는가?

오늘 내용 확인 3문제

  1. 300이 AC 02가 되는 과정을 7-bit groups와 continuation bit로 설명하라.
  2. -150을 zig-zag+varint로 쓰는 두 단계를 분리하고 왜 작은 음수에 유리한지 말하라.
  3. Length-delimited field가 선언한 length가 remaining bytes보다 클 때 안전한 decoder는 어떤 증거를 기록하고 어떻게 상태를 처리해야 하는가?

짧은 정답·채점 기준

어제 1IN_QUOTED 상태의 newline은 payload이며 quote가 닫힌 뒤 terminator만 record를 확정한다.
어제 2Encoding/BOM/limits, delimiter/quote/escape/newline/header, columns/null/type/timezone, version/reject/reconciliation/checkpoint/replay다.
어제 3New reader→versioned writer 순서, 2×2 golden bytes, shadow metrics, atomic pointer와 old contract rollback을 사용한다.
오늘 1300의 낮은 group 44는 다음 group이 있어 2C|80=AC, 남은 2는 마지막이라 02다.
오늘 2Zig-zag가 -150을 unsigned 299로 매핑하고 varint가 299를 AB 02로 쓴다. 0 근처 signed 값이 작은 unsigned에 모인다.
오늘 3Allocation/advance 없이 LENGTH_EXCEEDS_FRAME로 reject하고 frame identity, cursor, declared/remaining length, schema/reader version과 bounded hex를 기록한다.

채점: 각 2점, 총 12점. 10점 이상 통과. 오늘 답변에서 byte 계산, cursor invariant, failure window, 수치 limit, 관측 지표와 대안을 연결하면 면접 Level 3다.
