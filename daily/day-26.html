FILE FORMAT · WEEK 4 / DAY 26 · LESSON

nested data와 repetition/definition level

Logical tree를 leaf values와 level streams로 분해·복원 · 예상 학습 65분 + 실습 35분
한 줄 요약
Parquet은 nested object를 통째로 저장하지 않고 primitive leaf마다 values를 저장한다. Definition level은 leaf path가 어디까지 존재하는지, repetition level은 어느 repeated ancestor에서 연속되는지 나타내 null list·empty list·null element·새 row 경계를 손실 없이 복원한다.

1. 선수 용어 사전

2. 왜 중요한가

Columnar storage는 같은 leaf 값을 모아 압축·projection하기 좋다. 하지만 leaf values만 저장하면 null, 빈 list [], null element [null], tag가 null인 struct를 구분할 수 없다. 이 구조 정보가 definition/repetition levels에 있다.

Nested path 하나만 projection해도 values만 읽어서는 top-level row를 만들 수 없다. Reader는 해당 leaf의 levels도 decode해 row boundaries와 list offsets, validity bitmap을 만들어야 한다. 따라서 “100개 leaf 중 1개만 읽는다”는 비용에도 level bytes·parent offsets·materialization CPU가 포함된다.

핵심 불변식: Schema에서 계산한 max D/R, page의 level count, physical non-null value count, sibling leaf의 row/repetition 경계가 서로 맞아야 한다. 불일치는 조용히 padding하지 말고 corrupt 또는 incompatible schema로 격리한다.

각 leaf는 5개의 level records를 갖지만 id physical values는 2개, tag physical values는 1개뿐이다. Null은 value section에 저장하지 않는다.

4. CS 내부 동작

4.1 max D/R은 schema에서 결정된다

Root→leaf path를 걸으며 optional은 max D만 1, repeated는 max D와 max R을 각각 1 늘린다. Required는 어느 row에서도 존재하므로 level width를 늘리지 않는다. 필요한 bit width는 ceil(log2(maxLevel+1))다. Max D=4이면 0~4를 표현하므로 3 bits가 필요하다.

4.2 Definition level은 null의 위치를 보존한다

D가 낮다는 것은 path 중 더 위 ancestor에서 구조가 멈췄다는 뜻이다. 같은 “value 없음”도 D=0 null list, D=1 empty list, D=2 null element, tag path D=3 tag null로 구분된다. D=max D일 때만 decoder가 value stream에서 하나를 소비한다. 이 소비 횟수가 실제 encoded values count와 맞아야 한다.

4.3 Repetition level은 row·list 경계를 보존한다

R=0이면 어떤 repeated ancestor도 이전 record와 이어지지 않으므로 새 top-level row다. R=1은 이 schema에서 같은 orders list의 다음 element다. 더 깊은 list-of-list에서는 max R이 2 이상이며 level이 어느 repeated depth에서 새 element가 시작됐는지 알려 준다.

4.4 Data page에서 levels와 values는 별도 영역이다

Data Page V1의 payload는 repetition levels → definition levels → encoded values 순이며 해당 page 규칙에 따라 해석한다. Data Page V2는 level byte lengths를 header에 갖고 levels를 압축하지 않은 채 두며 value section만 compression 대상이 될 수 있다. V1/V2의 RLE length prefix 규칙도 다르므로 page type을 무시한 decoder는 offset부터 틀어진다.

4.5 Page 경계와 row 경계는 항상 같지 않다

공식 Thrift 계약상 Data Page V2는 R=0인 row boundary에서 시작하고 row를 page 사이에 나누지 않는다. V1은 OffsetIndex가 있으면 page가 row boundary에서 시작해야 하지만, 없으면 repeated row 중간에서 시작할 수 있다. Reader는 “새 page=새 row”로 가정하지 말고 level state와 index contract를 따라야 한다.

4.6 Vectorized materialization

Decoder는 R/D를 batch로 풀어 parent validity, list offsets, element validity를 만들고 D=max leaf records에서만 values를 채운다. Filter가 leaf에만 적용되어도 surviving parent rows와 element positions를 추적해야 한다. Deep nesting·wide lists·small batches에서는 offset construction, branch와 memory allocation이 projection I/O 절감보다 커질 수 있다.

상태 소유자·불변식·성공 시점

5. 실무 설계 판단

결정판단 기준과 이유
LIST schema새 writer는 공식 3-level LIST를 사용한다. Nullable list와 nullable element를 요구사항에서 따로 결정한다.
Legacy read2-level/이름이 다른 LIST는 공식 backward-compatibility rules와 engine matrix로 해석한다. 추측해 rewrite하지 않는다.
ProjectionLeaf bytes뿐 아니라 levels·dictionary·parent offsets 비용을 측정한다. Nested leaf 하나가 독립 scalar처럼 공짜는 아니다.
Filter pushdownANY/ALL, null element, empty list semantics가 engine마다 동일한지 golden rows로 검증한다.
Batch sizingTop-level rows보다 total elements와 variable-length bytes가 memory를 지배할 수 있다. Max list length·p99 child count로 제한한다.
Schema evolutionOptional leaf 추가는 대체로 안전해도 required/optional·list element nullability 변경은 D thresholds와 의미를 바꾼다. Reader/writer pair로 round-trip한다.

Best practice·anti-pattern·edge case·version 차이

  • Best: null list, empty list, [null], [{field:null}], multi-element, deep nested를 golden dataset에 모두 넣는다.
  • Best: Leaf path별 max D/R, decoded level count, non-null values consumed, top rows를 metric으로 남긴다.
  • Best: Projection/full read와 engine A/B의 logical JSON hash를 비교한다.
  • Anti-pattern: D가 max보다 작으면 모두 같은 null로 합친다.
  • Anti-pattern: 새 page마다 새 row를 시작하거나 sibling leaves를 record index로만 zip한다.
  • Anti-pattern: Legacy 2-level LIST를 새 writer가 계속 생산한다.
  • Edge: 한 top-level row의 거대한 list가 page/batch보다 커져 skew·OOM·slow retry를 만든다.
  • Edge: All-null leaf는 values bytes가 0이어도 levels로 rows를 표현할 수 있다.
  • Version: V1/V2 level placement·length prefix·row-boundary contract가 다르다. Page type과 실제 library support를 함께 확인한다.
  • Engine: Legacy LIST interpretation, nested predicate pushdown, field-id/name resolution은 엔진별 golden compatibility matrix로 검증한다.

7. 35분 실습: leaf level streams로 rows 복원

목표: Python 표준 라이브러리로 id/tag leaf의 (R,D,value)를 검증하고 null list·empty list·null element·struct를 복원한다. Repetition level 한 개를 변조해 sibling alignment corruption을 탐지한다.

사전 조건: Python 3.9 이상. 외부 package·파일·Docker가 필요 없다. 실제 Parquet RLE byte decoder가 아니라 level semantics simulator다.

실행 전 예측: id records 5개에서 physical int는 몇 개인가? Tag D=3과 D=4의 차이는? 네 번째 tag record의 R을 1→0으로 바꾸면 왜 값을 임의로 zip하면 안 되는가?

python3 - <<'PY' id_records = [(0,0,None),(0,1,None),(0,2,None),(1,3,7),(1,3,8)] tag_records = [(0,0,None),(0,1,None),(0,2,None),(1,3,None),(1,4,"x")] def validate(records, max_d, max_r): assert records and records[0][0] == 0 assert all(0 <= r <= max_r and 0 <= d <= max_d for r,d,_ in records) assert all((d == max_d) == (v is not None) for r,d,v in records) def reconstruct(ids, tags): validate(ids, 3, 1) validate(tags, 4, 1) assert len(ids) == len(tags) assert [x[0] for x in ids] == [x[0] for x in tags] rows = [] for (r,di,iv),(_,dt,tv) in zip(ids,tags): if r == 0: rows.append(None if di == 0 else []) if di == 0: assert dt == 0 elif di == 1: assert dt == 1 elif di == 2: assert dt == 2 rows[-1].append(None) else: assert di == 3 and dt in (3,4) rows[-1].append({"id":iv,"tag":tv if dt == 4 else None}) return rows rows = reconstruct(id_records, tag_records) print("rows=", rows) print("id_physical_values=", sum(d == 3 for _,d,_ in id_records)) print("tag_physical_values=", sum(d == 4 for _,d,_ in tag_records)) # Failure injection: sibling leaf의 같은 element를 새 row처럼 변조. bad_tags = tag_records.copy() bad_tags[3] = (0,3,None) try: reconstruct(id_records, bad_tags) except AssertionError: print("QUARANTINE: sibling repetition boundaries differ") else: raise AssertionError("corruption was not detected") assert rows == [None, [], [None,{"id":7,"tag":None},{"id":8,"tag":"x"}]] PY

예상 관찰: 5개 level records에서 id physical values는 2개, tag는 1개다. 정상 streams는 세 rows를 정확히 복원한다. Tag repetition boundary를 변조하면 sibling R streams 불일치로 quarantine 메시지가 나오며 잘못된 row를 반환하지 않는다.

실패 주입·자주 나는 오류·cleanup

  • 실패 주입: 네 번째 tag의 R=1을 R=0으로 바꿔 id와 tag가 다른 top-level row boundaries를 주장하게 한다.
  • 오류: Physical value 수를 level record 수로 가정하지 않는다. D=max D일 때만 value를 소비한다.
  • 오류: Null list·empty list·null element를 모두 Python None 하나로 바꾸지 않는다.
  • 오류: Simulator의 단순 sibling equality를 모든 arbitrary nested schema의 범용 join 알고리즘으로 사용하지 않는다.
  • 해결: 실제 reader는 schema path와 repeated ancestor depth에 따라 levels를 merge하고 count·range를 strict 검증한다.
  • Cleanup: Memory object만 사용하므로 파일·package·container가 남지 않는다.

8. 놓치기 쉬운 함정

  1. Group은 value column이 아니며 primitive leaves가 column chunks가 된다.
  2. Optional은 max D만, repeated는 max D와 max R을 모두 늘린다.
  3. D=max D record만 physical value를 소비한다.
  4. R=0은 새 top-level row이며 새 page와 같은 뜻은 아니다.
  5. Null list, empty list, null element, null field는 서로 다른 D 상태다.
  6. Leaf 하나 projection에도 level decoding과 parent offsets가 필요하다.
  7. Sibling leaves를 단순 record index로 zip하면 arbitrary nesting에서 틀릴 수 있다.
  8. Data Page V1/V2의 level length·compression·row-boundary 규칙은 다르다.
  9. Legacy 2-level LIST는 reader compatibility 대상이지 새 writer 권장안이 아니다.
  10. Nested predicate 성능보다 projection/full-read 결과 동일성을 먼저 검증한다.

9. 대기업 기술 면접 질문

Q1. Parquet이 nullable list와 nullable element를 leaf column에서 어떻게 구분합니까?

좋은 답변 구조: 3-level LIST schema를 제시한다 → leaf path의 optional/repeated nodes로 max D/R을 계산한다 → null list·empty list·null element·value의 D thresholds를 수치 예제로 보인다 → R=0/1로 row·element 경계를 설명한다 → D=max에서만 value 소비 → levels와 values로 offsets/validity를 복원한다.

Q2. Nested column 한 개만 projection하면 비용이 왜 1/N보다 클 수 있습니까?

좋은 답변 구조: Selected leaf value pages 외 R/D, dictionary, page headers를 읽는다 → decompress/level decode → parent validity·list offsets·selection을 만든다 → average/p99 element count와 variable bytes를 수치화한다 → cache/branch/allocation·batch trade-off를 측정한다 → flat denormalization 대안과 semantic cost를 비교한다.

Q3. 특정 engine에서 null list가 empty list로 읽힙니다. 대응하세요.

좋은 답변 구조: Snapshot·schema annotation·writer/reader version을 고정한다 → golden rows와 full/projection·engine A/B 결과를 수집한다 → leaf max D/R·raw levels·value counts로 최소 반례를 만든다 → legacy LIST interpretation/V1·V2 decoder/schema mapping 가설을 검증한다 → last-good rollback·quarantine → 표준 3-level immutable rewrite와 atomic republish를 설명한다.
