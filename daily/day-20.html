2. 왜 중요한가

“Field 추가는 compatible”은 절반짜리 답이다. Protobuf old reader가 new field를 unknown으로 넘겨도 JSON relay가 그것을 버릴 수 있고, new code가 field를 필수 업무값으로 쓰면 old bytes는 parse 후 실패한다. Avro reader field 추가도 default가 없으면 old writer record를 읽을 때 resolution error다.

반대로 parser가 즉시 실패하는 변경은 탐지하기 쉽다. 가장 위험한 것은 같은 Protobuf field number와 wire type을 다른 의미로 재사용해 old age=1이 new is_admin=true로 조용히 읽히는 경우다. 그래서 matrix의 셀 결과는 PASS/FAIL 두 값이 아니라 최소 parse, logical value, presence/unknown, domain invariant 네 층을 가져야 한다.

Lab 불변식: 모든 supported writer generation의 실제 bytes를 모든 supported reader build로 실행한다. 통과 셀에는 입력 checksum, schema fingerprint, runtime build, expected value, 조건 범위와 evidence link가 있어야 한다.

4. CS 내부 동작

4.1 Protobuf는 number와 wire type으로 경계를 찾는다

Tag는 (field_number<<3)|wire_type이다. 이름은 binary에 없다. 새 field number를 추가하면 old reader는 wire type으로 payload를 skip해 unknown으로 둘 수 있다. 반면 기존 number의 wire type을 VARINT에서 LEN으로 바꾸면 cross reader가 경계를 다르게 기대해 즉시 mismatch가 난다.

더 위험한 경우는 number와 wire type은 같지만 의미만 바꾸는 것이다. int32 age=1을 bool is_admin=1로 재사용하면 bytes 08 01은 두 schema 모두 정상이다. Parser error가 0이라도 권한이 상승할 수 있다. Field number는 identity이므로 삭제 뒤에도 reserve해야 한다.

4.2 조건부 호환은 value domain이 matrix 축이다

int32와 int64는 같은 VARINT wire type을 사용해 bytes를 parse할 수 있지만, new writer가 32-bit 범위를 넘는 값을 쓰면 old application에서 truncation 또는 overflow가 날 수 있다. 따라서 “type pair compatible”이 아니라 |value| ≤ 2,147,483,647 같은 guard를 rollout condition으로 둔다.

4.3 Avro는 writer schema로 bytes를 걷고 reader schema로 결과를 만든다

Avro binary에는 field name이 없으므로 exact writer schema가 data path의 일부다. Writer field가 reader에 없으면 값을 skip할 수 있다. Reader field가 writer에 없으면 reader default를 사용하고, default가 없으면 error다. Rename은 단순 문자열 변경이 아니라 reader alias로 old writer name을 연결해야 한다.

Avro int→long 같은 promotion은 resolution rule이지만 반대 방향은 자동으로 안전하지 않다. 또한 default가 parse를 성공시켜도 old bytes에 새 field 의미가 없었다면 business invariant는 별도로 확인해야 한다.

4.4 판정 state machine

단계검사와 전이

COMPAREExpected logical value와 차이가 있으면 LOSS 또는 SEMANTIC_FAIL.

5. 실무 설계 판단

판단Best practice와 이유
History 범위Queue TTL, object retention, offline client, rollback window 중 가장 긴 기간의 writer/reader generation을 inventory한다.
Fixture 선택Min/max/zero/null/absent, enum unknown, long string, malformed frame와 production percentile을 함께 넣는다.
증거 소유Producer team은 golden bytes, consumer team은 expected object·invariant, platform은 runner·fingerprint·retention을 소유한다.
조건부 변경Guard를 code assertion·metric·feature flag로 강제하고 old reader 0% 확인 뒤에만 범위를 넓힌다.
삭제/renameAdd → dual write/read → backfill → old write 중단 → 관찰 → reserve/alias 순서로 진행한다.
완료 시점CI matrix, canary pair metrics, historical replay와 sink reconciliation이 모두 통과한 뒤 완료한다.

Anti-pattern·edge case·runtime 차이

  • Registry green=배포 승인: Runtime·JSON bridge·presence·domain assertion이 빠져 있다.
  • R2(W2)만 테스트: Baseline과 두 cross edge가 없어 rolling deploy·rollback을 검증하지 못한다.
  • Sample 값 하나: 조건부 type change의 overflow 경계를 놓친다.
  • Parse exception만 실패: Silent truncation·default·권한 오해석을 통과시킨다.
  • Schema 객체로 bytes를 재생성: 실제 historical writer/runtime 특성이 사라진다. Golden bytes를 보존한다.
  • Adjacent만 통과: Long retention이면 V1↔V3 direct edge가 비어 있다.
  • 동시 배포 가정: Queue, cache, batch replay, mobile과 rollback 때문에 version skew는 남는다.
  • 언어 하나만 실행: Enum·unknown·overflow·generated API가 runtime별로 다를 수 있다.
  • Byte equality만 assertion: Protobuf serialization order는 canonical하지 않을 수 있다. Semantic equality와 unknown set을 본다.
  • 실패 row drop: Matrix runner 자체도 input=pass+fail reconciliation과 immutable report가 필요하다.

7. 40분 통합 실습: 변경 matrix를 코드로 판정

목표: Python 표준 라이브러리로 Protobuf-like tag stream과 Avro-like resolution을 구현해 safe·conditional·parse failure·semantic failure를 한 번에 분류한다.

사전 조건: Python 3.9 이상. 외부 package·protoc는 필요 없다. 교육용 bounded model이며 production runtime 대체가 아니다.

실행 전 예측: 다음 네 변경의 두 cross edge를 먼저 적는다: (A) 새 field 3 추가, (B) field 2 string→bool, (C) field 1 age→is_admin 같은 VARINT 재사용, (D) int32→int64에서 2,147,483,648 기록.

python3 - <<'PY' I32_MAX = 2_147_483_647 def varint(n): out = bytearray() while n > 0x7f: out.append((n & 0x7f) | 0x80); n >>= 7 out.append(n); return bytes(out) def field(no, wire, value): key = varint((no << 3) | wire) if wire == 0: return key + varint(value) raw = value.encode(); return key + varint(len(raw)) + raw def readv(buf, p): n = 0 for i in range(10): if p >= len(buf): raise ValueError("TRUNCATED_VARINT") b = buf[p]; p += 1; n |= (b & 0x7f) << (7*i) if b < 128: return n, p raise ValueError("OVERLONG_VARINT") def parse(buf, schema, max_len=256): p, obj, unknown = 0, {}, [] while p < len(buf): key, p = readv(buf, p); no, wire = key >> 3, key & 7 if no == 0 or wire not in (0,2): raise ValueError("BAD_TAG") if wire == 0: value, p = readv(buf, p) else: size, p = readv(buf, p) if size > max_len or size > len(buf)-p: raise ValueError("BAD_LEN") value, p = buf[p:p+size].decode(), p+size spec = schema.get(no) if spec is None: unknown.append((no,wire,value)); continue name, expected = spec if wire != expected: raise ValueError(f"WIRE_MISMATCH:{no}:{wire}!={expected}") obj[name] = value return obj, unknown def classify(label, raw, reader, invariant=lambda x: True): try: obj, unknown = parse(raw, reader) status = "SAFE" if invariant(obj) else "SEMANTIC_FAIL" print(f"{label:24}", status, obj, "unknown=", unknown) except Exception as e: print(f"{label:24}", "PARSE_FAIL", e) V1 = {1:("age",0), 2:("name",2)} V2_ADD = {1:("age",0), 2:("name",2), 3:("email",2)} W1 = field(1,0,21) + field(2,2,"kim") W2_ADD = W1 + field(3,2,"k@example.com") classify("R2_ADD(W1)", W1, V2_ADD) classify("R1(W2_ADD)", W2_ADD, V1) V2_TYPE = {1:("age",0), 2:("active",0)} W2_TYPE = field(1,0,21) + field(2,0,1) classify("R2_TYPE(W1)", W1, V2_TYPE) classify("R1(W2_TYPE)", W2_TYPE, V1) V2_REUSE = {1:("is_admin",0), 2:("name",2)} classify("R2_REUSE(W1)", W1, V2_REUSE, lambda o: o.get("is_admin") in (0,1)) print(" note: age=21 parsed, but authorization meaning is corrupted") def old_int32(n): return n if n <= I32_MAX else n - (1 << 32) for n in (100, I32_MAX, I32_MAX+1): observed = old_int32(n) status = "SAFE_UNDER_GUARD" if observed == n else "LOSS_OUTSIDE_GUARD" print("int64->old_int32", n, observed, status) PY

예상 관찰: Field 추가는 두 cross parser가 성공하고 old reader는 field 3을 unknown으로 본다. Wire type 변경은 두 방향 모두 mismatch다. 같은 wire type의 번호 재사용은 parse가 성공하지만 age=21이 권한 값으로 들어가는 semantic failure다. int64→old int32는 경계까지 조건부로만 안전하다.

7.2 Avro-like resolution matrix

python3 - <<'PY' def resolve(writer_record, reader_schema): out = {} for rname, spec in reader_schema.items(): candidates = [rname] + spec.get("aliases", []) hit = next((n for n in candidates if n in writer_record), None) if hit is not None: out[rname] = writer_record[hit] elif "default" in spec: out[rname] = spec["default"] else: raise ValueError("MISSING_NO_DEFAULT:" + rname) return out W1 = {"id":7, "amount":1000} cases = { "add_with_default": {"id":{}, "amount":{}, "currency":{"default":"KRW"}}, "add_no_default": {"id":{}, "amount":{}, "currency":{}}, "remove_amount": {"id":{}}, "rename_with_alias": {"id":{}, "total":{"aliases":["amount"]}}, "rename_no_alias": {"id":{}, "total":{}}, } for name, reader in cases.items(): try: print(f"{name:20}", "SAFE", resolve(W1, reader)) except Exception as e: print(f"{name:20}", "RESOLUTION_FAIL", e) same_old = {"id":7, "amount":1000} for default in ("KRW", "USD"): result = resolve(same_old, {"id":{},"amount":{},"currency":{"default":default}}) print("same bytes/default", default, "->", result, "SEMANTIC_REVIEW_REQUIRED") PY

예상 관찰: Add-with-default, reader field 제거, alias rename은 resolution이 성공한다. Add-without-default와 alias 없는 rename은 실패한다. Default 변경은 parse 성공이지만 같은 old data의 결과를 바꾸므로 semantic review가 필요하다.

7.3 실패 주입·자주 나는 오류·cleanup

  • 실패 주입: 첫 실습의 age=21을 1로 바꾸면 number reuse가 더 위험해진다. Parser와 간단한 bool invariant까지 모두 통과해 권한 오염이 완전히 silent하다.
  • 조건부 범위 누락: 100만 테스트하지 말고 boundary±1과 production max를 넣는다.
  • Alias 방향 혼동: Reader schema alias가 old writer name을 매칭하는지 실제 library로 확인한다.
  • Unknown=loss로 단정: Old reader의 unknown 보존과 downstream round-trip을 별도 assertion으로 둔다.
  • Default=업무 승인: Resolution 성공 뒤 currency·권한·unit invariant를 실행한다.

Cleanup: 두 명령은 파일·package·container를 만들지 않는다. 실제 golden bytes에는 PII가 있을 수 있으므로 보호 저장소와 access log를 사용하고 terminal·CI log에 raw payload를 남기지 않는다.

8. 놓치기 쉬운 함정

  1. Matrix 행/열에 R/W 방향을 명시한다.
  2. Baseline·target·두 cross edge를 모두 실행한다.
  3. Schema pair뿐 아니라 value range와 runtime을 축으로 둔다.
  4. Parse 성공, logical equality, presence/unknown, domain invariant를 따로 판정한다.
  5. 조건부 PASS를 SAFE로 승격하지 않는다.
  6. Historical bytes를 새 writer로 재생성하지 않는다.
  7. Avro exact writer schema fingerprint를 payload와 함께 보존한다.
  8. Protobuf field number는 삭제 후 reserve하고 재사용하지 않는다.
  9. JSON/Text bridge는 binary matrix와 별도 경로로 실행한다.
  10. CI 결과와 production canary/replay reconciliation을 연결한다.

9. 대기업 기술 면접 질문

Q1. Schema compatibility test platform을 설계하세요.

좋은 답변 구조: Producer/consumer·retention·rollback SLA를 묻는다 → writer×reader×runtime×value matrix를 그린다 → immutable golden bytes·fingerprint·expected object를 정의한다 → parse/presence/unknown/domain/round-trip gate를 단계화한다 → canary·quarantine·checkpoint·reconciliation과 비용 최적화를 방어한다.

Q2. Protobuf field number 재사용이 같은 wire type일 때 더 위험할 수 있는 이유는?

좋은 답변 구조: Tag에 name이 없고 number+wire type만 있다는 byte 원리를 말한다 → 08 01의 age→is_admin 예를 든다 → parser/registry가 성공해 silent corruption·PII/권한 사고가 됨을 설명한다 → reserve, expand-contract, golden semantic fixture와 rollback을 제안한다.

Q3. int32→int64 변경이 조건부 호환일 때 배포 절차를 설계하세요.

좋은 답변 구조: Old reader 비율과 max value를 수치로 확인한다 → boundary matrix와 overflow behavior를 runtime별 검증한다 → readers-first, writer guard≤INT32_MAX, metric·feature flag를 둔다 → old reader 0%와 rollback horizon 뒤 guard를 완화한다 → 손실 generation quarantine/replay 계획을 말한다.

10. 복습과 정답

어제 내용 회상 3문제

  1. Implicit 0과 explicit optional 0의 wire·presence 차이는?
  2. Unknown field가 binary relay와 JSON/manual copy에서 다르게 동작하는 이유는?
  3. Avro reader default가 writer field 생략 허가가 아닌 이유는?

오늘 내용 확인 3문제

  1. Compatibility matrix의 최소 네 칸과 각 운영 의미를 쓰라.
  2. Protobuf field 추가, wire type 변경, 같은 wire type 번호 재사용을 네 등급으로 분류하라.
  3. Avro reader field 추가·rename을 안전하게 만들 조건과 semantic 검사를 설명하라.

짧은 정답·채점 기준

어제 1Implicit unset/0은 empty bytes로 합쳐진다. Explicit unset은 empty·has false, explicit 0은 08 00·has true다.
어제 2Binary object는 raw unknown set을 재직렬화하지만 JSON은 numeric tag 의미를 담지 못하고 manual copy는 known accessor만 옮긴다.
어제 3Avro writer는 default와 같아도 field를 encode한다. Reader default는 writer에 없는 field를 read-time에 materialize한다.
오늘 1R1(W1) baseline, R2(W2) target, R2(W1) backward/replay, R1(W2) forward/rollback이다.
오늘 2새 number 추가는 binary wire-safe, 같은 field의 wire type 변경은 parse fail, 같은 number/type 의미 재사용은 semantic fail이다. int 폭 변경은 value guard가 필요한 conditional일 수 있다.
오늘 3추가 field는 reader default, rename은 reader alias가 필요하다. 그 뒤 default·unit·presence·aggregate가 old bytes에서 같은 의미인지 검증한다.

채점: 각 2점, 총 12점. 10점 이상 통과. Matrix 축, byte mechanism, silent failure, rollout guard, quarantine·rollback·reconciliation을 연결하면 면접 Level 3다.
